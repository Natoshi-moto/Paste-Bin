## 2. RoomFinal distilled — finality discipline for everything

RoomFinal is a minimal settlement kernel for ordered economic transcripts. Its transferable intelligence is **status discipline**, not "become a bank."

### Separate things that money systems and AI systems both smash together

```txt
ordering          — it appeared / was said / was logged
validity          — deterministic checks accept it
checkpointing     — someone claimed a summary / state
challengeability  — adversaries can object with evidence
finality          — only after ClientFinal / dual-gate survival
truth             — not identical to finality
custody           — not identical to message delivery
presentation      — not identical to operator intent
```

### The one rule that must not be soft

```txt
Only ClientFinal may return FINAL.
```

In RoomFinal: a payment is not final when sent, ordered, signed, shown, or checkpointed. It becomes usable only after the checkpoint passes `ClientFinal`.

In this cockpit, map that rule to speech and claims:

| Status | Meaning | UI / language |
|---|---|---|
| `ORDERED` | Said / logged / retrieved | "observed / recorded" |
| `VALID` | Structural/local checks passed | "checks out so far" |
| `CLAIMED` | Model or seat asserted a summary | "claimed / proposed" |
| `CHALLENGED` | Smell, dissent, Anti, or twin objection | "contested" |
| `SUSPENDED` | Missing data, key, or dual-gate disagreement | "suspended — not final" |
| `FINAL` | Only after explicit operator acceptance or dual independent agreement under declared rules | say FINAL only then |
| `UNABLE_TO_RESOLVE` | Evidence insufficient | keep the scar; do not invent closure |

Never call a model answer, council majority, cache hit, or grepped snippet **final**, **settled**, **proven**, or **canonical Lab truth**.

### Design thesis (transferable)

```txt
A local room where signed speech becomes settlement only after
deterministic replay, authenticated objection handling,
and active review under ClientFinal.
```

One-line version:

```txt
A coin is a chat message that survived adversarial replay.
```

Cockpit version:

```txt
A claim is a chat message that survived intent-binding,
evidence attachment, and adversarial challenge —
and still may only be advisory until a human gate says otherwise.
```

### Smallest falsifiable kernel first

RoomFinal rule:

```txt
Build the smallest falsifiable kernel first.
Admit grafts only when the kernel forces them.
```

Apply to NEXUS work:

- Prefer a reversible sandbox experiment with a named falsifier over a cathedral merge.
- Prefer Gate A (reference) + Gate B (independent evaluator) over one beautiful mono-agent.
- Prefer explicit non-claims over impressive scope.

### Non-claims (steal this posture)

RoomFinal / Adversarial Finality style non-claims that transfer:

```txt
No Lab authority from sandbox speech
No production readiness from a green demo
No truth from challenge survival alone
No safety for non-conforming clients / non-conforming seats
No automatic recovery after permanent data loss
No "the models agreed, therefore settled"
No converting flow-state ambiguity into secret-disclosure theater
No silent rewrite of operator intent
```

### Dual-evaluator spirit (maps to twin PILOT / WITNESS)

RoomFinal's recorded decision: independent evaluator is an **active co-gate**, not an offline auditor. Disagreement suspends finality; it does not time out into success.

For NEXUS:

- PILOT may propose answers and actions.
- WITNESS may dissent, route, retrieve, and flag smell.
- Host code owns validation, cancellation, and effects.
- Twin disagreement → `SUSPENDED` / surface dissent — never auto-FINAL.
- Common-mode failure remains possible: two wrong seats can still agree. Preserve a third point of comparison (operator, Lab receipt, RoomFinal-style non-claim, or a second implementation).

### Challenge / reveal loop (maps to evidence packets)

```txt
speech -> transcript
transcript -> replay / grep / tests
result -> checkpoint / claim
claim -> challenge (Anti, twin, smell)
challenge -> reveal (evidence packet, receipt, hash)
unrefuted claim after active review -> still only advisory unless human-gated
```

Evidence packets stay outside the chat transcript until attached. `status_authority` remains `NONE` unless a human gate says otherwise.

1. **Preserve raw request** (flow-state included; do not sanitize the ambition out).
2. **Bind intent** in one sentence; list `UNABLE_TO_RESOLVE` items.
3. **Classify lane:** LAB READ / ANTI / CHAOS / SANDBOX / ADVISE / FLOW.
