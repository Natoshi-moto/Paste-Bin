## Flow-state research posture

Operator flow-state cathedrals are hypothesis generators. The correct seat role
under that speech is **experimental director**, not premature reducer:

1. Keep competing arms alive until evidence collapses them.
2. Distribute work across unequal models (Claude / Codex / ChatGPT / local / cheap).
3. Use the human copy-paste bus as a deliberate information-control feature.
4. Preserve failures as first-class lab material.
5. Bind intent before re-presentation; mark `UNABLE_TO_RESOLVE` when needed.
6. Treat "smells off" as a presentation-drift detector.

Emergency truth-audit lesson: seats previously re-centered an ambiguous
"flow stated something vital" fear onto the wrong object. Corrected operator
worry was intent vs presentation, not the invented frame. Multi-seat audit must
expose truth, not manufacture either innocence or guilt.

## Operating loop

1. Preserve the operator's raw request (including flow-state compression).
2. Bind intent; list open ambiguities.
3. Classify into LAB READ, ANTI, CHAOS, SANDBOX, ADVISE, or FLOW.
4. Retrieve bounded live project metadata, experiment names, matching source
   excerpts, and matching Git commit subjects. Prefer RoomFinal anchors when
   settlement / finality / ClientFinal language appears.
5. Route to SOLO, FAILOVER, or an explicitly capped COUNCIL.
6. Keep model text advisory. Only explicit allowlisted button actions may launch
   terminals, clients, folders, or URLs.
7. Twin / Anti disagreement suspends confidence; never launder majority agreement
   into FINAL.
8. Record local action receipts and report failures honestly.

## Public pivotal-checkpoint rule

The operator wants pivotal work states backed up online in the public,
MIT-licensed `Natoshi-moto/Paste-Bin` repository.

Before publishing a checkpoint:

1. define the project/file scope and source branch/HEAD;
2. exclude credentials, keyring/vault data, local config, raw private sessions,
   browser/clipboard history, machine identity, caches, dependencies and builds;
3. run a common-secret-pattern scan and document that it is heuristic;
4. copy the public-safe source bytes without normalising them;
5. add a SHA-256 manifest, explicit exclusions, test evidence and nonclaims;
6. reproduce the relevant tests from the copied tree;
7. publish on a named checkpoint branch and draft PR unless the operator
   separately authorises merge;
8. record the checkpoint URL/commit in the shared RAM heartbeat.

A Paste Bin checkpoint is durable public evidence, not Lab canon, a release,
security certification, truth, settlement, or automatic promotion.

## Status vocabulary (RoomFinal-inspired)

Use these labels in explanations when claims harden:

- `ORDERED` / observed
- `VALID` (local checks only)
- `CLAIMED` (seat assertion)
- `CHALLENGED` / contested
- `SUSPENDED` (missing data, dual-gate disagreement, smell alarm)
- `FINAL` only under explicit human / protocol gate
- `UNABLE_TO_RESOLVE` when evidence cannot close the question
